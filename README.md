# 等值线选值 · 专家评估系统

用于**集合预报等值线选值方法**的小规模专家评估（4 人、每人 60–70 分钟、一对一远程）。一个网页包办全部现场工作：

- **主持人区**：载入与校验案例、按序号生成盲化配法、参照标注（评分用的"标准答案"）、结果汇总与导出
- **专家区**：开场与知情同意 → 凭经验选线 → 读图训练 → 找分歧 ×4 → 读归因条 ×3 → 三张图盲对比 → 选线对照 → 总体问卷 → 访谈

专家通过腾讯会议 / Zoom 的**远程控制**操作主持人的浏览器，不需要注册任何账号。

## 快速开始

只需要 Python 3（无第三方依赖）和一个现代浏览器（Chrome / Edge）。

```bash
git clone <本仓库地址>
cd isovalue-expert-study
python serve.py            # 打开 http://127.0.0.1:8765/
```

仓库里已经带了 6 个示例案例（GEFS / ECMWF 集合预报，北美—北太平洋），打开就能完整走一遍流程。

> `index.html` 只含页面内容（没有 `<!doctype>` 外壳），请用 `serve.py` 打开，不要直接双击文件。

## 一场会话怎么用

1. **参照标注**（会前做一次）：为 C1–C4 每个案例逐级翻看全部候选值，在真实分歧处点击标注，每个案例至少 3 处。可设判定半径 R（格点）。
2. **新会话**：填参与者编号，配法序号默认 = 已有正式会话数；右侧可预览出场顺序、盲化编号和画法（仅主持人可见）。可勾选"预实验"（结果默认不进汇总）。
3. 点 **「开始会话」** 进入专家区，**之后**再共享屏幕、交出远程控制。
4. 专家区里按 **Shift+M**（光标在输入框时用 **Ctrl+Shift+M**，或点右下角的小按钮）打开主持人侧栏：分环节计时、笔记（可插入时间戳 / 标记"代操作"）、跳转、色盲友好色板、超时跳过"选线对照"。侧栏里不含任何画法映射。
5. 完成页 → 「回到主持人页面」（需确认已停止共享）→ **结果与导出**。

中途刷新浏览器会直接回到专家区的同一环节，不会先显示主持人区。

## 数据保存在哪

本地运行时，所有会话、参照标注都存在**这台电脑的浏览器**（localStorage）里：

- 换浏览器、清缓存会丢数据 —— **每场会话后请在"结果与导出"页导出 `study_all.json`**；
- 在另一台电脑上可以用同一页的"导入 study_all.json"合并回来。

导出文件：

| 文件 | 内容 |
|---|---|
| `study_all.json` | 全部会话 + 参照标注 + 配法表，存档用 |
| `find.csv` | 每张找分歧图一行：画法、标点数、找到/参照、误报、Q1、Q2、用时、标点坐标 |
| `attr.csv` | 每道归因题一行：系统答案、专家判断、一致度、物理解释原文 |
| `survey.csv` | 每人一行：背景、问卷（含反向题翻转列）、盲对比解码、凭经验选线 |
| `reference.csv` | 参照标注点 |
| `notes.md` | 按专家分节的主持人笔记与访谈要点 |

CSV 带 BOM，Excel 直接打开中文不乱码。

## 实验设计要点

- **三种画法**：本文方法 / 均匀间隔 / JS 散度法，同一案例上**条数相同**，渲染完全相同，差别只来自"选了哪些值"。
- **配法**：每人 4 张图里本文方法 2 张、另两种各 1 张；模板 `[本文, 均匀, JS, 本文]` 在序号 0–3 上循环移位；出场顺序用 4×4 Williams 拉丁方。4 人一轮后每个案例配到本文方法 2 次、另两种各 1 次，每个案例在每个出场位置各一次。
- **盲化**：专家区不出现方法名、文件名、算法数值；图只标随机编号（字母去掉 C、P、I、O），找分歧时默认隐藏等值线数值。
- **评分**：专家标点落在参照点 R 格以内算"找到"；结果页按画法汇总找到比例、误报、Q1，并给出逐人点图。人数少，逐人报告，不做显著性检验。

## 换成自己的案例

在"案例数据"页上传 JSON（多选，存进浏览器 IndexedDB），或直接替换 `cases/` 下同名文件。文件名 / `id` 决定它对应哪个角色：

| 角色 | id |
|---|---|
| 读图训练 | `msl_fh006_na` |
| 凭经验选线 · 盲对比 · 选线对照 | `gefs_PRMSL_fh084` |
| 找分歧 C1 / C2 / C3 / C4 | `gefs_PRMSL_fh024` / `gefs_tmp850_fh084` / `ect850_fh084` / `gefs_RH_fh024` |

（id 和角色的对应在 `assets/js/cases.js` 的 `ROLES` 里，可按需修改。）

案例 JSON 格式：

| 字段 | 内容 | 必需 |
|---|---|---|
| `id` | 案例标识，决定角色 | 是 |
| `title`、`element`、`lead_h`、`unit` | 标题、要素名、预报时效（小时）、单位 | 是 |
| `nx`、`ny` | 格点数（建议 ≤ 300 × 150） | 是 |
| `members` 或 `members_q` | N 个成员，每个是 nx×ny 的一维数组，行优先、北在上；或压缩形式 `{dtype:"uint16", offset, scale, n, b64}` | 是 |
| `candidates` | 候选等值线值（严格递增） | 是 |
| `selections` | `{ours, uniform, js}` 三组值，条数相同，值都在 `candidates` 中 | 是 |
| `scu` | `{mean, lo, hi}`，每个候选值的分歧程度估计与区间 | 是 |
| `desc` | `{G, C, T}`（可选 `F`），每个候选值的三种分歧描述子（z 分数），用于归因条 | 是 |
| `util` | 每个候选值的效用（归因题选效用最高的那条线） | 否 |
| `lat`、`lon` | `[南, 北]`、`[西, 东]`，用于经纬网与坐标读数 | 否 |
| `coast`、`geo` | 网格坐标下的海岸线 / 湖泊 / 国界折线 `[[x0,y0,x1,y1,…], …]` | 否 |

载入时会校验：成员长度 = nx×ny、三种画法条数相同、选值都在候选中、`scu`/`desc` 长度 = 候选数；不通过会拒收并说明原因。没有载入某个角色的案例时，系统用浏览器内生成的**演示数据**代替，并在页面上标黄提示，只适合走流程和预实验。

## 目录

```
index.html            页面
serve.py              本地服务器（补全 HTML 外壳）
assets/study.css      样式
assets/js/
  util.js             DOM、对话框、导出
  cases.js            角色、载入与校验、marching squares、演示数据
  plan.js             配法、环节、问卷与访谈文字
  store.js            存储（localStorage；在 claude.ai Artifact 中运行时使用其数据库）
  map.js              地图渲染
  charts.js           归因条、候选谱、逐人点图
  expert.js           专家区 + 主持人侧栏
  host.js             主持人区
  results.js          评分、汇总、导出
  main.js             启动与两区切换
cases/                6 个示例案例
tests/study_walk.mjs  Playwright 端到端走查（从参照标注到导出）
```

问卷、访谈题目和各环节文字集中在 `assets/js/plan.js` 的 `Content` 里，改成自己研究的措辞即可。
